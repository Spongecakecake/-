「做到」— 和重要的人立约，把每个目标走完

立下目标 · TA 监督也送礼 · 每天互相打气 · 达成时拆礼物，再收到一本属于你们的大结局回忆录
文档版本：V0.2（初稿） 日期：2026-10-23 状态：待评审 平台：移动端 App（iOS / Android）形态待定，见 Q1 相对 V0.1：目标类型泛化、新增礼物承诺与双向搭子、新增大结局回忆录

1背景与问题

1.1 目标用户与典型场景

主要用户：心里有目标、却总差一口气的人
20–35 岁为主。想做的事很多——减肥、早起、备考、戒糖、读完书单、坚持健身、学一门技能——但总在懒惰、贪吃、拖延中反复开始、反复放弃。
典型时刻
① 晚上刷到别人的成果，冲动立誓"这次一定坚持"；
② 第三天就破功，"反正没人知道"，心安理得放弃；
③ 就算做成了，也只是静静结束，没有人庆祝、没有留下什么。

1.2 问题拆解：目标为什么坚持不下去

问题具体表现产品应对
目标模糊、没有截止"我要变好"无法衡量、没有期限，拖延无成本FR-02 三类结构化目标模板：数值型 / 习惯型 / 项目里程碑型，明确周期与成功标准
放弃零成本承诺只对自己做出，偷懒没人知道、没有代价FR-05 邀请熟人担任搭子监督人 / 见证人；目标公开化
缺乏即时正反馈目标回报遥远，努力当天看不到甜头FR-04 心愿礼物（TA 承诺送的礼就在终点）+ 里程碑 + 勋章；FR-08 点赞加油
一个人战斗太孤独监督其实是双向的陪伴：一方打卡坚持，一方每天惦记，双方都需要被回应FR-05/FR-08 双向鼓励：监督人的每日鼓励、主人的答谢、"互相搭子"关系
一次破功就崩盘漏卡 / 一顿暴食后心态上"全盘放弃"FR-03 补卡券、休息天；FR-06 驳回而非直接判负
结束时没有沉淀努力过的日子散落在聊天记录和相册里，很快被遗忘FR-09 大结局回忆录：自动汇编成一本可翻看、可分享的旅程记录

1.3 产品要实现的可观察结果

成功标准（定性，数据目标 TBD） 用户能独立完成一次完整闭环：立一个带期限、带成功标准的目标 → 邀请一位重要的人做搭子监督人（TA 可同时承诺一份达标礼物）→ 周期内打卡、被审核、被鼓励，双方持续互动 → 到期得到明确的成败判定 → 成功则拆礼物、收到系统生成的大结局回忆录并分享/珍藏。
本产品的情感内核 "监督"只是表层动作，真正的留存动力是关系：有人把你的目标放在心上，每天等你打卡；你也不愿让那个准备了礼物、天天为你加油的人失望。目标达成的那一刻，礼物是奖励，而共同走完的这段经历本身，才是回忆录要留住的东西。

3产品目标与定位

项说明
一句话定位「做到」是一款帮用户为任何想坚持的目标公开立约、由重要的人监督鼓励并承诺礼物、达成后拆礼庆祝并自动生成大结局回忆录的打卡见证 App。
目标范围通用目标，首期内置模板覆盖高频场景：减脂 / 健身运动、早起早睡、学习备考 / 阅读、戒断（戒糖戒酒戒熬夜）、攒钱、技能练习（乐器 / 语言 / 绘画）等；支持自定义目标。
核心用户有想达成的目标但自律不足、需要外部推动与情感陪伴的人；以及愿意为重要的人投入时间和一份礼物的"搭子"（监督人同样是产品用户，而非纯工具人）。
触发起点用户在某个冲动时刻打开 App 立目标；或收到朋友的邀请链接"我想请你当我的监督人"。
完成条件目标到期，依据打卡记录与期末成果，由规则 + 监督人给出明确成败判定；成功则解锁礼物、生成大结局回忆录。
信任基础① 打卡有证据且可审核；② 成功标准与礼物承诺提前确认、事后不反悔改规则；③ 礼物承诺是人情约定而非平台交易，平台不经手资金与物流。

3.1 设计原则

  • 轻工具、重关系：打卡录入 30 秒内完成；产品重心放在两人的互动、礼物与回忆上。
  • 监督是陪伴，不是审判：驳回要给理由、给鼓励；不提供嘲讽、罚钱公示等羞辱机制。
  • 双方都是主角：监督人的鼓励、陪伴也被记录、被感谢、进入回忆录。
  • 礼物轻量、人情优先：允许"一杯奶茶""一次家务全包"这样的小承诺；不引导高价礼物，未成年人与大额场景设限制（9.4）。
  • 规则前置、判定留痕：成功标准、审核规则、礼物承诺在开始前确认，进行中不可单方更改。
  • 健康安全：仅针对减脂 / 体重类目标生效（9.3），不鼓励极端减重。

4范围（P0 / P1）

首期交付最小完整闭环：立约（建目标、定礼物、邀人）→ 履约（打卡、审核、双向互动）→ 收尾（判定、拆礼、回忆录）。

4.1 P0：首期必做 P0

编号能力为什么是闭环必需

FR-10消息与提醒（打卡、待审核、互动、礼物动态；免打扰）履约留存与召回
FR-11契约卡 / 打卡卡 / 拆礼卡 / 回忆录封面等站外分享卡片裂变与公开承诺压力

4.2 P1：已识别但首期不做 P1

详见第 8 节，摘要：礼物的线上交易闭环（电商链接 / 红包代付 / 礼品卡）、回忆录实体印刷与视频版、健康数据与穿戴设备接入、AI 识别防作弊、多人小队 PK 与排行榜、付费专业监督、官方人工仲裁队列、会员体系。

4.3 明确排除

  • P0 不做任何资金托管、支付清算、现金对赌；平台不卖货、不做礼物电商。
  • 不做课程库、直播课、医疗诊疗、代餐电商。
  • 不做匿名树洞、陌生人私信交友等与履约无关的社交。

角色定义核心权力与义务

6核心旅程与状态流转

6.1 主旅程（P0 闭环）

1立约选目标模板、定规则，写下"如果做到，我想要……"心愿
2邀人把目标+心愿发给 TA："来监督我，做到了送我这个？"
3承诺监督人接受并认下礼物，附上第一句鼓励
4履约陪伴每日打卡交作业，TA 审核、点赞、催更；你答谢，双向互动
5判定拆礼到期判定；成功→礼物解锁，仪式化拆开，线下兑现
6回忆录系统汇编大结局：过程、金句、寄语、礼物，成册分享/珍藏

6.2 礼物承诺旅程（差异化主线）

① 写心愿
主人建目标时添加心愿礼物：名称、图片、预算备忘，可多选。可指定"希望由 XX 送"。
② 发邀约
邀请监督人的卡片带上心愿："目标做到的话，你愿意送我 ____ 吗？" 监督人可：认下这份 / 换一份自选礼物 / 只监督不送礼。
③ 明约或惊喜
明约：承诺立即出现在目标页"礼物位"，是全程看得见的动力；惊喜：进行中只显示"TA 准备了一个神秘礼物 🎁"，拆礼时揭晓。
④ 加码
进行中监督人 / 见证人可随时加码（"坚持满 21 天再加一杯奶茶"），同样可选明约或惊喜。
⑤ 拆礼兑现
成功后礼物解锁，逐一点开看寄语；双方线下完成后互相点"已兑现/已收到"。失败则承诺不兑现，可"顺延到下一期"。

6.3 关键状态流转规则

流转规则
草稿 → 进行中若已添加监督人，需至少 1 位接受邀请后生效，开始日顺延至满足条件次日 假设，TBD；无监督人可直接生效，但流程中强提示"邀一位搭子，完成率更高"
进行中 → 成功到达结束日且满足该目标类型成功规则（9.2）：系统初判 + 监督人 72 小时内确认；多监督人取多数，平票 TBD
进行中 → 失败到期未达标，或有效打卡率低于阈值（默认 60% TBD）且补卡券用尽
进行中 → 已终止主人可主动终止，二次确认并填原因；礼物承诺自动失效并通知承诺人；时间线保留
结束之后只读；可"再来一期"，继承目标参数、角色与顺延的礼物承诺（受邀人需再次确认）

7功能需求（P0）

标注：P0 首期 · V0.2 新增/重写 · TBD 待决策 · 假设 暂定 · 强规则 健康/资金/不可逆操作。

FR-01账号注册登录与个人档案P0

目的

建立身份与关系链；健康相关信息只在需要时采集，不做全量问卷。

  1. 手机号验证码登录，支持微信 / Apple 第三方登录 渠道按上架要求，TBD。
  2. 首次登录仅设置：昵称、头像；性别、年龄区间选填。身高、当前体重延迟到创建体重类目标时才采集，并在采集前展示《健康风险提示与免责声明》（9.3），勾选确认后方可创建。
  3. 个人主页展示：进行中 / 已完成的目标、勋章墙、"送出的礼物 ×N / 收到的礼物 ×N"（人情档案，仅自己可见明细，公开页只显示数量徽章如"最佳搭子"）。
  4. 注销：公开内容下架、关系解除、进行中的礼物承诺标记失效并通知对方；注销前若担任他人监督人，引导先退出或与对方协商更换（9.5）。

  • 体重输入超出 30–250kg、身高 120–230cm 判定误输入并阻断。
FR-02创建目标（三类模板 + 自定义）P0V0.2 泛化

目的

把任何"想坚持的事"变成参数明确、规则可判定的契约。

三类目标

所有模板均可自定义文案；用户也可直接选"自定义目标"手动选择判定方式。

通用字段

  • 周期：21 / 30 / 60 / 90 天快捷项，自定义 7–180 天；开始日默认次日。
  • 每周休息天：0–2 天，默认 1 TBD；休息天免打卡、不计违约。
  • 打卡内容要求：按模板默认勾选，可改（照片 / 数值 / 时长 / 一句话），勾选后成为监督人审核依据。
  • 里程碑：数值型按进度自动建议、习惯型按天数建议（第 7/21/结束日），可增删；里程碑可绑定加码礼物（FR-04）。
  • 隐私：公开（广场可见）/ 仅受邀 / 仅自己，默认仅受邀。
  • 心愿礼物：创建流程中引导添加（FR-04），可不填直接发布。

处理规则

  • 发布后进行中目标：成功规则、周期、目标值不可修改；其他字段（打卡要求、礼物、隐私）修改需监督人确认且留痕。
  • 体重类模板额外执行健康校验（9.3）：减重速率提示、BMI 下限阻断。
  • 创建完成生成"契约卡"：目标 + 周期 + 心愿礼物 + 监督 / 见证席位，直接用于邀请与分享。

异常

  • 必填缺失禁止发布并定位；同一用户同时最多 1 个体重类进行中目标、进行中目标总数 ≤3 TBD。
  • 里程碑型若所有里程碑均为非必选，要求至少转为一个必选，否则无法判定成功。

FR-04心愿礼物与激励体系P0V0.2 核心新增

目的

让终点有一个具体、有人情味的期待——"TA 答应我的礼物就在那里"，比抽象积分更能拉动每日行动；平台全程不经手资金与物流。

4.1 心愿礼物（主人侧）

  • 创建目标时及目标进行中均可添加心愿：礼物名称（1–20 字）、图片（可选）、一句话说明、参考预算（数字备忘，可隐藏）；单目标心愿 ≤5 件。
  • 可标记心仪承诺人（"希望由 @TA 送"），仅作为邀请时的建议，不构成强制。
  • 礼物不分贵贱：提供轻量灵感库（"一杯奶茶""请吃火锅""一双跑鞋""一次旅行""家务全包一个月""随便挑一本书"），文案引导心意而非价格。

4.2 礼物承诺（搭子侧）

  • 监督人接受邀请时三选一：认下主人指定的心愿 / 自选一份礼物承诺 / 先只当监督人（不送礼完全不影响角色权责，避免人情绑架）。
  • 见证人接受邀请后也可承诺加码小礼物；进行中任何受邀角色均可随时加码（常绑定里程碑："满 21 天加一杯奶茶"）。
  • 每份承诺选择模式：明约（礼物名与承诺人全程可见）/ 惊喜（进行中目标页只显示"🎁 TA 准备了一个神秘礼物"，内容与寄语在拆礼时揭晓）。
  • 承诺时可写一句寄语（可设为"拆礼时才显示"）；承诺即时生成系统通知告知主人（惊喜模式不透露内容）。

4.3 拆礼与兑现

  • 目标成功：结果页进入拆礼流程，礼物逐一点开（开礼物动效 + 寄语展示）；加码礼物按里程碑解锁情况分别处理（未达标的加码不解锁）。
  • 线下兑现：双方自行完成购买 / 赠送；产品内提供"标记已兑现"（承诺人）与"确认收到"（主人）两步确认，完成后礼物进入双方人情档案与回忆录。
  • 目标失败：承诺不兑现、不追责；承诺人可一键选择"约定顺延到下一期"或只发一句鼓励；顺延的承诺在主人开启新目标时自动带入等待确认。
  • 目标终止：承诺自动失效并通知承诺人，不产生任何违约责任。

4.4 边界与防滥用 强规则

  • 全链路固定文案："礼物是朋友间的心意约定，由双方线下自行兑现，平台不参与购买、支付、配送，也不强制履行。"承诺页、心愿页、拆礼页三处展示。
  • 不提供收货地址填写、转账入口、商品外链（P0）；不显示"礼物市场"类交易导向页面。
  • 承诺人可在目标开始前无条件撤销；目标开始后撤销需主人确认（防止半途抽走动力），撤销记录不公开 规则假设，TBD。
  • 参考预算为选填且仅双方可见；不做礼物价格排行；禁止承诺现金、虚拟货币及违规商品（词库 + 举报，9.4）。
  • 未成年账号：礼物相关功能默认关闭，需成年后开启 准入策略见 Q5，TBD。

FR-05邀请搭子监督人与见证人P0V0.2 重写

邀请流程

  1. 主人选角色 → 站内好友或微信邀请链接；邀请卡片展示目标摘要 + 心愿礼物 + 文案"我想认真做完这件事，你来当我的搭子监督人好不好？做到了，你答应我的礼物可就要兑现啦～"。
  2. 被邀人落地页先看权责说明：监督人 = 每天看打卡、通过 / 驳回、到期判定（约每天 1 分钟）；并展示礼物邀约，三选一（FR-04.2）。
  3. 接受后角色生效、进入见证墙，系统通知主人；监督人接受时被引导写下第一句鼓励（这句话将进入回忆录"启程"章节）。
  4. 婉拒可附一句鼓励（仅主人可见），不公开、不影响双方其他关系。

双向鼓励（陪伴感的核心）

  • 监督人侧：工作台每条打卡可"通过 + 选一句鼓励贴纸 / 写一句话"；驳回必须附理由，且引导同时留鼓励语；每日可主动催打卡一次（带俏皮文案模板，限频防骚扰）。
  • 主人侧：收到审核 / 鼓励后可一键回"爱心 / 感谢"，或回复文字；连续被鼓励时系统引导"也去看看 TA 的目标"。
  • 互相搭子：双方在各自目标中互为监督人时，关系页出现"互相搭子"标识与双人聚合视图（两人的进度并排、共同坚持天数）；P0 不做强制结对 PK（P1）。
  • 鼓励互动（每日鼓励、答谢、驳回后重交通过的瞬间）自动标记为"搭子瞬间"，作为回忆录素材（FR-09）。

边界

  • 监督人 1–2 人；见证人上限 建议 20，TBD；进行中可追加。
  • 监督人退出：目标在 72h 内无监督人时打卡免审核但每日提醒主人补人，超 7 天标记"无人监督"，成败规则不变；其礼物承诺随退出失效（若已承诺）。
  • 主人可更换监督人（无待审核打卡时），通知双方、审核历史保留。
  • 催打卡 / 邀请限频：同一对象每日 1 次；被邀人可关闭此类邀请。
FR-06打卡审核与到期结果判定P0

  • 驳回必选理由（证据不清 / 疑似不实 / 与目标不符 / 其他）并允许补文字；主人当天可修改重交，不消耗补卡券。
  • 审核时限：24h 未处理提醒 1 次；48h 未处理自动通过并标注"超时自动通过"。

  1. 结束日 20:00 TBD 锁定数据，生成《履约报告》：有效打卡率、数值变化 / 完成率、里程碑、驳回与补卡记录。

FR-09大结局回忆录P0V0.2 核心新增

目的

把一段共同走完的经历自动沉淀成"作品"：它是给坚持者的颁奖礼，是给搭子的感谢信，也是产品最值得被转发的传播资产。成功目标生成《大结局回忆录》，失败 / 终止目标生成调性不同的《旅程纪念册》。

9共享规则与异常

9.1 成功判定规则（创建时锁定、双方确认）

  • 数值型：结束日成果数值达到目标值（变小 / 变大按设定方向）+ 有效打卡率 ≥60%（默认 TBD，休息天不计入分母）；体重类取期末确认体重，未称重取最后 7 天末次记录并标注。
  • 习惯型：完成率 ≥80%；戒断类"未做到 / 破戒"记录 ≤2 次 TBD。
  • 里程碑型：全部必选里程碑在截止前完成（需打卡证据且通过审核）。
  • 有效打卡 = 审核通过或超时自动通过；被驳回未重交、缺卡未补均不计。

违规礼物（现金、违禁品、高价诱导）命中词库或举报核实：移除礼物内容、通知双方，情节严重限制功能（9.4）

9.3 健康安全规则（仅体重类目标） 强规则

  • 首次创建体重类目标前展示健康声明（孕期 / 哺乳期、进食障碍史、心血管 / 糖尿病、未成年人遵医嘱），确认后记录。
  • 减重速率 0.3–1.0 kg/周显示合理区间，>1.0 弹警示（不阻断），目标体重低于 BMI 18.5 阻断 阈值需专业顾问确认，TBD。
  • 广场不允许催吐、长期断食、减肥药等内容，命中限曝光并给健康提示。

9.4 隐私、内容与举报

  • 隐私三级：公开 / 仅受邀 / 仅自己，默认仅受邀；精确数值（体重、金额）默认不进广场。
  • 回忆录他人内容授权清单（FR-09）；打卡照片界面禁用保存，协议中声明技术防护边界 TBD。
  • 举报处置：明显违规先下架后复核；举报双向匿名；软删除留存期限依合规意见 TBD。
  • 注销：回忆录含双方内容，注销方内容从公开链接下架；另一方账号内的回忆录保留但移除注销方头像昵称与寄语（默认匿名化），公开链接关闭 TBD。
