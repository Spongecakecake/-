二 · 背景与目标

2.1 背景

产品核心假设是「别人是动机的供给侧」，既有设计已覆盖见证人（强关系）链路，但围观者（弱关系）无参与路径，社区扩张缺少自发动机。插旗体系把围观者变成玩家：立目标可公开为「旗」，围观者护旗（鼓励）或拔旗（激将），按旗的结局与行为质量结算积分，兑换平台特权。

2.2 要解决的问题

  • 弱关系用户参与成本高（只能成为见证人），社区密度不足；
  • 传播缺素材（打卡截图无戏剧性）；
  • 打卡真实性无验证体系（Pact 死因），插旗玩法会放大刷分动机。

2.3 成功指标与口径

三 · 名词与术语定义

术语定义
旗目标选择「全部公开」后生成的公开实体，含进度、留言流、成色、状态；一面旗对应一个目标
插旗创建旗的行为；主角=插旗人
护旗 / 拔旗围观者对旗的两种站队：护旗=留言鼓励；拔旗=从官方话术模板选择诱惑内容
成色旗的验证强度等级：仅自证 / 见证人点验 / 自动核验（V2 增加：机构结果），决定积分乘数
威胁值近 7 日拔旗强度量化值，展示于旗面，用于营造对抗氛围（不直接改变目标数据）
复活窗旗落后 7 天内可用重启券换新旗的期间；期间结算分按复活规则重算
宿敌对决V2：同目标模板的两面旗互为对手，任一方落幕即分胜负，双方都满期则共斗胜利
信任分用户信用分（初始 100），影响可参与能力；实锤造假清零
点验 / 抽检点验=见证人发起的限时取证请求；抽检=系统随机发起的取证请求

五 · 方案对比与选型说明

选型点方案 A方案 B结论
拔旗默认状态 默认关闭，插旗时勾选开启 默认开启，可关闭 选 A。首批用户心理承受度未知，关闭率红线 ≤8% 未验证前不从默认开启起步

九 · 业务流程与状态流转

9.1 旗状态机

待生效（插旗确认前）→ 确认 → 生效中 → 期满且全里程碑 → 已达成（终态，可生成喜报）
生效中 → 主动放弃 / 期满未达 → 已掉落（复活窗 7 天）→ 用重启券 → 生效中（新旗，旧留言归档）
已掉落 → 7 日未复活 → 已落幕（终态，仅战况卡）
任意状态 → 实锤造假认定 → 已作废（终态，处罚生效，申诉成功可回退到原状态）
状态允许操作不允许
生效中打卡举证、站队留言、降级/转私密、免战生成喜报
已掉落重启（消耗券）、查看留言合集新站队留言（冻结）
已达成 / 已落幕生成卡片、回看、宿敌结算（V2）一切新站队
已作废申诉插旗（禁插 90 天）、积分使用

9.2 站队主流程

围观者进入旗详情 → 选阵营（护 / 拔）→ 护：输入留言（≤100 字）即上墙 / 拔：选官方模板（或自定义→审核队列）→ 上墙 → 计行为分（结算中）→ 旗结局触发 → 结算分按成色乘数计算 → T+7 发放（复活窗可能重算）

9.3 点验 / 抽检流程

发起（见证人手动 / 系统随机）→ 主角收到「牵挂式」请求 → 2h / 24h 内实时取证 → 系统核验（真实性规则 + 风控复核）→ 通过：信任 +1 / 缺席：信任 −5 → 高抽检池联动（FR-E04）
